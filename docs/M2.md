# M2 — Offers and prices

A part with a distributor link is a label. A part with an offer ladder is a
purchase decision: which packaging, what the next break costs, and whether
buying ten more would have been cheaper. M2 stores real offers and real price
breaks, fetched from DigiKey and entered by hand for everyone else.

## The real payload

Verified against the live API, `POST /products/v4/search/keyword` returns:

```json
"ProductVariations": [
  {
    "DigiKeyProductNumber": "296-OPA211AIDRGRCT-ND",
    "PackageType": {"Id": 2, "Name": "Cut Tape (CT)"},
    "MinimumOrderQuantity": 1,
    "StandardPricing": [
      {"BreakQuantity": 1,   "UnitPrice": 11.26,  "TotalPrice": 11.26},
      {"BreakQuantity": 10,  "UnitPrice": 8.814,  "TotalPrice": 88.14},
      {"BreakQuantity": 25,  "UnitPrice": 8.2012, "TotalPrice": 205.03},
      {"BreakQuantity": 100, "UnitPrice": 7.5285, "TotalPrice": 752.85}
    ]
  }
]
```

One product carries several variations — Tape & Reel, Cut Tape, Digi-Reel — and
each has its own SKU, MOQ and ladder. All of them are offers; a reel and a cut
strip are different things you can buy.

## Definition of done

1. A part page lists every offer with its packaging, SKU, MOQ and break ladder.
2. Given a quantity, the page and the API say which offer is cheapest in total,
   not which unit price is smallest.
3. Offers can be refreshed from DigiKey for one part or every stale part.
4. Offers can be entered by hand for distributors with no API.
5. A price ladder that punishes buying more is reported, not silently stored.
6. Nothing about a build or a BOM depends on M2 yet; it lands as its own layer.

## Schema

```sql
CREATE TABLE offer (
  id INTEGER PRIMARY KEY,
  part_id INTEGER NOT NULL REFERENCES part(id) ON DELETE CASCADE,
  distributor_id INTEGER NOT NULL REFERENCES distributor(id),
  sku TEXT NOT NULL,
  packaging TEXT,                      -- 'Cut Tape (CT)', 'Tape & Reel (TR)'
  url TEXT,
  currency TEXT NOT NULL DEFAULT 'USD',
  minimum_quantity INTEGER NOT NULL DEFAULT 1,
  stock_quantity INTEGER,              -- NULL when the supplier does not say
  source TEXT NOT NULL,                -- 'digikey' | 'manual'
  fetched_at TEXT,
  created_by TEXT,
  UNIQUE (part_id, distributor_id, sku)
);

CREATE TABLE price_break (
  id INTEGER PRIMARY KEY,
  offer_id INTEGER NOT NULL REFERENCES offer(id) ON DELETE CASCADE,
  quantity INTEGER NOT NULL CHECK (quantity > 0),
  unit_price_micros INTEGER NOT NULL CHECK (unit_price_micros >= 0),
  UNIQUE (offer_id, quantity)
);
```

**Money is integer micro-dollars.** A resistor at `$0.02366` is `23660`. Floats
in a price column are how a BOM ends up four cents off and nobody can say why.
Rendering divides by 1e6 and trims trailing zeros, keeping at least two
decimals.

## Fetching

`app/pricing.py`, reusing `app/enrich.py`'s token, budget and throttle helpers:

- `POST /products/v4/search/keyword` with `{"Keywords": mpn, "Limit": 5}`.
- Keep only products whose `ManufacturerProductNumber` matches the part's MPN
  after normalisation — a keyword search returns near misses, and attaching
  another part's prices is worse than attaching none.
- One offer per variation. A refresh **replaces that offer's breaks wholesale**
  inside one transaction; it never appends a second ladder, because a stale
  break next to a new one produces a price that exists nowhere.
- Offers that disappear from the supplier are marked `fetched_at` current with
  no breaks, and the page says "no longer listed" rather than deleting history.

## Choosing an offer

`best_offer(conn, part_id, quantity)` returns the cheapest **total** cost and
the offer that wins:

- an offer is eligible when `quantity >= minimum_quantity`;
- the applicable break is the largest `quantity <= requested`;
- total = `quantity * unit_price` at that break;
- ties break toward the smaller MOQ, then the earlier-fetched record.

This is the point of the milestone: at 25 pieces the Cut Tape at `$8.2012` beats
the reel whose MOQ is 3000, and at 5000 the reel wins by a wide margin. Sorting
by "lowest unit price" answers a question nobody asked.

## Price-break audit

`shelfmark offers audit` walks each ladder and reports every consecutive pair
where `q2 * p2 < q1 * p1` — the next break costs less in total than the smaller
quantity. That is the situation that made a 42-piece line cost more than 50,
and it must be visible before the order goes out.

Output names the part, the distributor, the SKU and the two breaks.

## CLI

```
shelfmark offers refresh --ipn SK-00001
shelfmark offers refresh --all --stale-days 7
shelfmark offers audit
```

`refresh --all` skips parts with a fresh ladder, so a routine run is cheap.
Progress is printed one line per part, and a failure on one part does not stop
the run.

## API

| method | path | notes |
|--------|------|-------|
| `GET` | `/api/parts/{ipn}/offers?quantity=N` | offers with computed unit price and extended cost, cheapest first; `best` names the winner |
| `POST` | `/api/parts/{ipn}/offers` | manual offer: distributor, sku, packaging, url, minimum_quantity, and a `breaks` list |
| `DELETE` | `/api/offers/{id}` | removes an offer and its ladder |
| `POST` | `/api/parts/{ipn}/offers/refresh` | fetches from DigiKey now; engineer |

Reads are viewer, writes are engineer.

## Interface

A **Prices** panel on the part page:

- a table, one row per offer: packaging, distributor, SKU, MOQ, stock, and the
  ladder as `1+ $11.26 · 10+ $8.81 · 25+ $8.20 · 100+ $7.53`;
- a quantity box that highlights the winning row and shows the total;
- the winning row marked **best** and the row's total shown, so the cheapest
  answer is stated rather than inferred;
- a refresh button (engineer) and a small "fetched 3 days ago" note;
- a manual add form with break rows.

An offer with no breaks renders "no price listed" — never `$0.00`, which is a
number and therefore a lie.

## Tests

- the real payload shape parses into one offer per variation with every break
- a keyword result whose MPN differs is ignored
- refresh replaces a ladder rather than appending to it
- a refresh that returns nothing marks the offer as no longer listed
- `best_offer` picks the reel at 5000 and the cut tape at 25
- an offer below its MOQ is not eligible
- a break boundary uses the break at exactly that quantity
- money renders from micro-dollars without float drift (`0.02366`)
- `audit` flags an inverted pair and stays quiet on a normal ladder
- manual offers round-trip through the API; viewer gets 403 on writes
