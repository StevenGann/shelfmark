# M1 — Parts and identity

Implementation order for this milestone. Everything here must land together; the
milestone is not done until the acceptance section passes.

## Scope

Parts, internal part numbers (IPN), manufacturer part number (MPN) normalisation,
parts list API and web UI, create/edit. Stock, offers, BOMs and substitution are
later milestones — do not build them now, but do not design anything that
prevents them.

## Schema (migration `migrations/0002_parts.sql`)

```sql
CREATE TABLE part (
  id INTEGER PRIMARY KEY,
  ipn TEXT NOT NULL UNIQUE,
  mpn TEXT NOT NULL,
  mpn_norm TEXT NOT NULL,
  manufacturer TEXT NOT NULL,
  description TEXT,
  category TEXT,
  parameters_json TEXT NOT NULL DEFAULT '{}',
  commodity_class_id INTEGER,
  design_status TEXT NOT NULL DEFAULT 'active'
    CHECK (design_status IN ('active','nrnd','obsolete','do-not-use')),
  notes TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE (mpn_norm, manufacturer)
);
CREATE INDEX part_mpn_idx ON part(mpn_norm);
CREATE INDEX part_category_idx ON part(category);

-- One row. IPNs are never reused, so a deleted part leaves a hole.
CREATE TABLE ipn_counter (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  last_value INTEGER NOT NULL
);
INSERT INTO ipn_counter (id, last_value) VALUES (1, 0);
```

Timestamps are UTC ISO-8601 with a `Z` suffix (`2026-11-25T06:00:00Z`). No local
time in the database.

## IPN

Format `SK-00001`, prefix from `settings.ipn_prefix` (default `SK`), five digits.
Allocation is a single transaction: read `last_value`, increment, insert the part,
commit. Two concurrent creates must not receive the same IPN. The IPN is assigned
once and is immutable — `PATCH` never changes it.

## MPN normalisation

`normalise_mpn(s)`:

1. Upper-case.
2. Strip everything that is not a letter or digit.
3. Return the result.

Two MPNs that differ only in punctuation are the same part. Two that differ in a
digit are not — `RC0402JR-7D4K7L` normalises to `RC0402JR7D4K7L` and
`RC0402JR-074K7L` to `RC0402JR074K7L`, and they are different parts. This is the
case that caught the pricing spreadsheet out.

The uniqueness rule is `(mpn_norm, manufacturer)`. A duplicate create returns
HTTP 409 with the existing IPN in the body.

## Repository API (`app/repo/parts.py`)

Plain functions over a connection, no ORM:

- `create_part(conn, *, mpn, manufacturer, description=None, category=None, notes=None, design_status="active") -> dict`
- `get_part(conn, ipn) -> dict | None`
- `list_parts(conn, *, q, category=None, limit=50, offset=0) -> tuple[list[dict], int]` — total count included
- `update_part(conn, ipn, **fields) -> dict | None`
- `count_parts(conn) -> int`

Search `q` matches `ipn`, `mpn`, `mpn_norm`, `manufacturer` and `description`,
case-insensitively.

## HTTP API

| Method | Path | Behaviour |
| --- | --- | --- |
| GET | `/api/parts` | `q`, `category`, `limit`, `offset`; returns `{"items": [...], "total": n, "limit": l, "offset": o}` |
| POST | `/api/parts` | JSON body; 201 with the part; 409 duplicate; 422 invalid |
| GET | `/api/parts/{ipn}` | 200 or 404 |
| PATCH | `/api/parts/{ipn}` | partial update, IPN immutable; 200 or 404 |

`GET /api/health` keeps working exactly as it does now.

## Web UI

Server-rendered Jinja2. No JavaScript build step, no CDN, no SPA.

- `/` — parts list: search box (submits on Enter, and a visible button), category
  filter, table of IPN / MPN / manufacturer / description / design status, row
  links to the detail page, "New part" button, pagination. Empty state that says
  what to do rather than "no data".
- `/parts/new` — create form.
- `/parts/{ipn}` — detail with an inline edit form and a save button.
- Form posts redirect (303) back to the detail page on success. Validation errors
  re-render the form with the message and the entered values preserved.
- Duplicate MPN+manufacturer shows the existing IPN in the error.

Mobile is a requirement, not a nicety:

- `<meta name="viewport" content="width=device-width, initial-scale=1">`.
- At 390 px wide there is no horizontal scrolling; the parts table becomes a list
  of cards (IPN and MPN prominent, description secondary).
- Touch targets at least 44 px tall. Form inputs at 16 px font so iOS does not
  zoom on focus.
- Works one-handed: primary actions reachable at the bottom or in a sticky bar.

Design: dark-friendly, system font stack, no external assets. Keep the CSS in one
`static/app.css`.

## Tests

- `tests/test_mpn.py` — the punctuation case above, both directions; idempotence;
  empty/whitespace input is rejected rather than silently normalised to "".
- `tests/test_ipn.py` — format, monotonicity across 25 allocations, immutability
  under update, and that a failed create (duplicate) does not consume a number.
- `tests/test_parts_api.py` — create/read/list/patch, 409 on duplicate, 404 on
  missing, pagination totals.
- `tests/test_parts_ui.py` — create a part through the HTML form, follow the
  redirect, assert the IPN appears on the detail page and in the list; assert the
  form re-renders with an error on duplicate.
