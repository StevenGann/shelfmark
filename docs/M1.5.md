# M1.5 — API keys

Design is in `docs/AUTH.md`; this is the implementation order. The milestone is
not done until the acceptance section passes and the deployed instance refuses
an unkeyed request.

## Scope

One authentication mechanism for everything: the REST API, the HTML UI, the CLI.
No users, no passwords, no sessions.

## Schema (`app/migrations/0003_api_keys.sql`)

```sql
CREATE TABLE api_key (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  key_hash TEXT NOT NULL UNIQUE,
  prefix TEXT NOT NULL,
  role TEXT NOT NULL CHECK (role IN ('viewer','engineer','admin')),
  created_at TEXT NOT NULL,
  last_used_at TEXT,
  revoked_at TEXT
);
CREATE INDEX api_key_hash_idx ON api_key(key_hash);
```

## Key handling (`app/auth.py`)

- `generate_key() -> tuple[str, str, str]` returns `(plaintext, sha256_hash, prefix)`.
  Plaintext is `smk_` + `secrets.token_hex(20)`; `prefix` is the first 8 hex
  characters, for display only.
- `hash_key(s) -> str` is SHA-256 hex.
- Lookup is a single query on `key_hash`, compared with `hmac.compare_digest`
  after the fetch. A revoked key is a `401`, not a `403`.
- `touch_last_used(conn, key_id)` writes at most once a minute per key; hold the
  last-seen timestamp in memory so a read-only request does not become a write
  on every call.

## Dependencies

```python
require(role)   # returns the key row; raises 401 when absent/invalid, 403 when the role is insufficient
```

Role ordering: viewer < engineer < admin.

Source of the key, in order: `Authorization: Bearer …`, `X-API-Key: …`, the
`smk_session` cookie (UI only). The cookie holds the key **id**, signed with
`SHELFMARK_SECRET_KEY`, never the key itself.

Apply at router level, not per endpoint, so a new route cannot be born
unauthenticated: `/api/*` requires viewer unless the endpoint declares more.
`/api/health`, `/static/*`, `/login` and `/logout` are public.

`SHELFMARK_AUTH=none` disables enforcement; it is refused (startup error) when
`SHELFMARK_ENV=production`.

## Bootstrap

On startup, after migrations: if `api_key` is empty, either take
`SHELFMARK_BOOTSTRAP_KEY` or generate one; write it to
`$SHELFMARK_DATA_DIR/bootstrap-key.txt` (0600) and log it once with the prefix
`BOOTSTRAP KEY`. Never log a key at any other time.

## Key management

- `GET /api/keys` (admin) — id, name, prefix, role, created_at, last_used_at, revoked_at. Never the hash.
- `POST /api/keys` (admin) — `{name, role}` → 201 `{id, key, name, role}`; the plaintext appears once.
- `POST /api/keys/{id}/revoke` (admin) — idempotent, 204.
- CLI: `shelfmark key create --name X --role admin`, `shelfmark key list`, `shelfmark key revoke --name X`.
  Add `[project.scripts] shelfmark = "app.cli:main"`.

## UI

- `GET /login` — one field, "API key", plus a button. No username.
- `POST /login` — verify, set `smk_session` (HttpOnly, SameSite=Lax, Secure when
  the request is https, `max_age` 30 days), redirect to `next` or `/`.
- `POST /logout` — clear cookie, redirect to `/login`.
- Every HTML route requires the cookie; an unauthenticated browser request
  redirects to `/login?next=<path>` rather than returning 401 JSON.
- The header shows the key name and role, and a logout button.

## Rate limiting

In-memory fixed window per key id: 600 requests/minute (`SHELFMARK_RATE_LIMIT`,
0 disables). Over the limit → 429 with `Retry-After`. Unauthenticated requests
are limited by client IP at a tenth of the rate. Keep the implementation under
40 lines and note in a comment that it is per-process, which is correct because
the deployment is one process by contract.

## Tests

- `tests/test_auth.py` — no key → 401; wrong key → 401; viewer on POST → 403;
  engineer on POST → 201; revoked key → 401; `SHELFMARK_AUTH=none` → 200 without a key.
- `tests/test_keys_api.py` — create/list/revoke; the plaintext is returned once
  and the list never contains it; duplicate name → 409.
- `tests/test_login_ui.py` — unauthenticated `/` redirects to `/login`; posting a
  valid key sets the cookie and the list page renders; logout clears it.
- `tests/test_rate_limit.py` — with the limit set to 3, the fourth request is 429
  with `Retry-After`.
- Existing tests must be updated to send a key through a fixture; none of them may
  bypass auth by monkeypatching the dependency.

## Acceptance

```
ruff check .            # clean
ruff format --check .   # clean
mypy app                # clean
pytest -q               # all green
```

Plus: the running container refuses `curl /api/parts` without a key, accepts it
with one, and `/login` works in a browser at 390 px wide.

## Do not

- Do not add a user table, password hashing, sessions, OAuth or SSO.
- Do not store plaintext keys anywhere except the one-time bootstrap file and the
  one-time create response.
- Do not add an external dependency for auth, cookies or rate limiting.
