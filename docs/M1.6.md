# M1.6 — Human logins: username and password

Supersedes the "API keys only" section of the earlier design: keys stay for
machines, people get accounts. Read `docs/AUTH.md` first — it is the spec, this
is the work order.

## Migration `0004_users.sql`

```sql
CREATE TABLE app_user (
  id INTEGER PRIMARY KEY,
  username TEXT NOT NULL,
  username_norm TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  role TEXT NOT NULL CHECK (role IN ('viewer','engineer','admin')),
  created_at TEXT NOT NULL,
  last_login_at TEXT,
  disabled_at TEXT
);
CREATE TABLE user_session (
  id INTEGER PRIMARY KEY,
  token_hash TEXT NOT NULL UNIQUE,
  user_id INTEGER NOT NULL REFERENCES app_user(id) ON DELETE CASCADE,
  created_at TEXT NOT NULL,
  last_seen_at TEXT NOT NULL,
  expires_at TEXT NOT NULL
);
CREATE INDEX user_session_user_idx ON user_session(user_id);
```

## Module `app/users.py`

- `hash_password(password) -> str` and `verify_password(stored, password) -> bool`
  using `hashlib.scrypt` and the format in `docs/AUTH.md`.
- `needs_rehash(stored) -> bool`, and rehash on successful login when true.
- `create_user(conn, username, password, role)`, `get_user_by_username`,
  `list_users`, `set_role`, `set_disabled`, `set_password`, `count_users`.
- `validate_password(password, username)` raising `ValueError` with a message
  that is safe to show the user.

## Module `app/sessions.py`

- `start(conn, user_id) -> token`, `resolve(conn, token) -> user | None`,
  `touch(conn, session_id)`, `end(conn, token)`, `end_all_for_user(conn, user_id, except_id=None)`.
- Expired rows are deleted on resolve.

## Web routes (`app/web.py`)

- `GET /setup`, `POST /setup` — only when `count_users() == 0`; otherwise 404.
  All other UI routes redirect to `/setup` while there are no users.
- `GET /login`, `POST /login` — `username`, `password`, optional `next`. On
  success: create session, set cookie, `303` to `next` (validated to a local
  path). On failure: `401`, same message either way, and count toward the login
  rate limit.
- `POST /logout` — delete the session row, clear cookie, `303 /login`.
- `GET /account`, `POST /account` — change own password; requires the current
  password; deletes every other session on success.
- `GET /users`, `POST /users`, `POST /users/{id}/role`, `POST /users/{id}/disable`
  — admin only. A user cannot disable or demote themselves, and the last enabled
  admin cannot be demoted or disabled.
- Replace the API-key cookie dependency on UI routes with a session dependency.
  API-key cookies are removed entirely: `/api/*` takes headers only.

## Rate limiting

Keep the existing module. Add `allow(f"login:{ip}:{username_norm}", 5, window=900)`
support — the current fixed window is 60 seconds, so extend `allow` to take a
window argument rather than hard-coding it.

## Tests

- setup creates the first admin, then `/setup` is 404
- login succeeds, sets an HttpOnly cookie, and the UI renders
- wrong password and unknown username both return 401 with identical text
- a disabled user's existing session stops working immediately
- password change invalidates other sessions but not the current one
- last admin cannot be demoted or disabled; self-demotion is refused
- 6 failed logins in a row → 429 with `Retry-After`
- `/api/parts` still works with a header key and refuses a session cookie alone

accepts a key.

## Do not

- No password in chat, in logs, in the repository, or in an environment variable.
- No third-party dependency for hashing, sessions or cookies.
- No "remember me", no password reset by email, no 2FA. If a password is lost an
  admin sets a new one from `/users`.
