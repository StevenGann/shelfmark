# M1.7 — Part pages: links, package, and hosted assets

What a part page should answer without leaving the building: who makes it, what
it is, what package it comes in, where to buy it, what it looks like, and the
datasheet — with the datasheet and the image stored locally rather than hotlinked.

Enrichment is driven by the DigiKey Product Information API v4, which returns
manufacturer, product URL, datasheet URL, photo URL and the full parameter set
including `Package / Case` for a single MPN in one call. Verified against
`DAC81416RHAT` and `GRM155R71C104KA88D` before this was written.

## Schema (`0005_part_assets.sql`)

```sql
CREATE TABLE manufacturer (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  name_norm TEXT NOT NULL UNIQUE,
  website TEXT
);

CREATE TABLE distributor (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  name_norm TEXT NOT NULL UNIQUE,
  search_url_template TEXT NOT NULL,   -- contains {mpn}
  product_url_template TEXT             -- contains {sku}
);

CREATE TABLE part_link (
  id INTEGER PRIMARY KEY,
  part_id INTEGER NOT NULL REFERENCES part(id) ON DELETE CASCADE,
  kind TEXT NOT NULL CHECK (kind IN ('datasheet','manufacturer','distributor')),
  label TEXT NOT NULL,
  url TEXT NOT NULL,
  distributor_id INTEGER REFERENCES distributor(id),
  sku TEXT,
  source TEXT NOT NULL,                -- 'digikey', 'manual', 'template'
  fetched_at TEXT,
  UNIQUE (part_id, kind, url)
);

CREATE TABLE part_asset (
  id INTEGER PRIMARY KEY,
  part_id INTEGER NOT NULL REFERENCES part(id) ON DELETE CASCADE,
  kind TEXT NOT NULL CHECK (kind IN ('image','datasheet')),
  source_url TEXT NOT NULL,
  rel_path TEXT NOT NULL,
  content_type TEXT NOT NULL,
  bytes INTEGER NOT NULL,
  sha256 TEXT NOT NULL,
  fetched_at TEXT NOT NULL,
  status TEXT NOT NULL CHECK (status IN ('ok','failed')),
  error TEXT,
  UNIQUE (part_id, kind, source_url)
);

CREATE TABLE fetch_job (
  id INTEGER PRIMARY KEY,
  part_id INTEGER NOT NULL REFERENCES part(id) ON DELETE CASCADE,
  kind TEXT NOT NULL,                  -- 'enrich'
  status TEXT NOT NULL,                -- queued|running|done|failed
  attempts INTEGER NOT NULL DEFAULT 0,
  next_attempt_at TEXT NOT NULL,
  last_error TEXT,
  created_at TEXT NOT NULL,
  finished_at TEXT
);
```

`part` gains `package TEXT` and `manufacturer_id INTEGER NOT NULL REFERENCES
manufacturer(id)`, and its uniqueness moves from `(mpn_norm, manufacturer)` to
`(mpn_norm, manufacturer_id)`. SQLite cannot add a NOT NULL foreign key to an
existing table, so the migration rebuilds `part`: create the new shape, copy the
rows, backfill `manufacturer` from the distinct strings, drop and rename. Do this
now, before anything references `part`.

Seeds: DigiKey, Mouser, LCSC, TME, Farnell, Octopart with their search templates;
Mouser again with `https://www.mouser.com/ProductDetail/{sku}`.

## Asset storage

- `SHELFMARK_ASSET_DIR`, default `/data/assets`. Inside it,
  `parts/<ipn>/datasheet.pdf` and `parts/<ipn>/image.jpg`. The database stores the
  path relative to the root; nothing stores an absolute path.
- Writes are atomic: write `<name>.tmp` in the same directory, then `os.replace`.
- Serving: `GET /assets/{rel_path}` behind the viewer role, resolving the path
  under the root and rejecting anything that escapes it (`..`, absolute paths,
  symlinks out). Correct `Content-Type` from the stored row, `Cache-Control:
  private, max-age=86400`, `Content-Disposition: inline` for PDFs.
- A failed fetch records a `part_asset` row with `status='failed'` and the error,
  so the UI can say "no image, last attempt failed" instead of looking like
  nobody tried.

## Enrichment (`app/enrich.py`)

One MPN, one call: `GET /products/v4/search/{mpn}/productdetails` on the DigiKey
API — not keyword search, so there is no ambiguity to resolve. From the response:

| Field | Source |
|---|---|
| manufacturer | `Manufacturer.Name` → upsert `manufacturer` |
| manufacturer link | `manufacturer.website` if seeded, else the DigiKey manufacturer page |
| package | `Parameters` entry `Package / Case`, normalised |
| datasheet | `DatasheetUrl`, downloaded |
| image | `PhotoUrl`, downloaded |
| DigiKey link | `ProductUrl` |
| other distributors | `search_url_template` with the MPN |

Downloads: 30 s timeout, 20 MB cap for datasheets, 5 MB for images, content types
`application/pdf`, `image/jpeg`, `image/png`, `image/webp`; anything else is a
recorded failure, not a guess. Follow redirects but refuse a final URL that is
not http(s).

Budget: one request per second, and a daily cap of 1,000 calls
(`SHELFMARK_DIGIKEY_DAILY_BUDGET`). Exhausting the budget leaves jobs queued with
`next_attempt_at` at the next day, never dropped.

Failure classes: 404 means "not in the catalogue" and is terminal; 429 backs off
and retries; 5xx retries with exponential backoff; a missing credential leaves
the job queued and surfaces "credentials not configured" in the UI.

## Package normalisation (`app/packages.py`)

DigiKey writes `0402 (1005 Metric)`, `40-VFQFN Exposed Pad`, `8-SOIC (0.154",
3.90mm Width)`. Keep the human-facing string as the package field but normalise a
searchable key: `0402`, `VQFN-40`, `SOIC-8`. Rules, each with a test:

- imperial chip sizes 0201, 0402, 0603, 0805, 1206, 1210, 1812 and 2512, taken from the
  leading token
- `<n>-<family>` → `<FAMILY>-<n>`, upper-cased (`8-SOIC` → `SOIC-8`,
  `40-VFQFN` → `VQFN-40`)
- `(1005 Metric)` and similar parentheticals dropped
- unchanged when nothing matches — never invent a package

When a KiCad footprint arrives (M3) it wins over the DigiKey string:
`R_0402_1005Metric` → `0402`, `SOIC-8_3.9x4.9mm_P1.27mm` → `SOIC-8`.

## UI

Part page, mobile first, image above the fields under 640 px:

- image with a package-drawing placeholder when absent
- IPN, MPN, manufacturer (linked), package chip, category, description
- a link row: Datasheet (local, with a "source" link beside it), DigiKey, Mouser,
  LCSC, Octopart
- "Fetch metadata" button, showing the last fetch time and any failure
- empty state that says what it will fetch, not just that it is empty

List page: package column (and filter), thumbnail when one exists.

## Jobs

`POST /api/parts/{ipn}/enrich` (engineer) queues a `fetch_job` and returns 202
with the job id. `shelfmark enrich --all|--ipn SK-00001 [--force]` runs the queue
in-process. The scheduler tick added in M2 will drain the same table; nothing in
this milestone depends on it having arrived.

## Tests

- migration backfills manufacturers and keeps every part's IPN
- `partdetails` parsing from a recorded fixture (one IC, one 0402 passive)
- package normalisation table, including the "unchanged when unknown" case
- download accepts pdf/jpeg and rejects `text/html` with a recorded failure
- asset path traversal is refused
- enrich is idempotent: a second run makes no duplicate links and no duplicate
  assets
- a queued job with no DigiKey credential stays queued with a clear error

## Limits, stated up front

- Mouser, LCSC, TME, Farnell and Octopart get **links only** until they have API
  credentials. Mouser's API is free but account-holder only.
- DigiKey product photos are often a representative photo of the package rather
  than the exact part; they are still better than an empty box and are labelled
  as supplier images.
- The DigiKey API returns no manufacturer website, hence the seeded table and the
  fallback link.
